✅ 3. 업데이트 UI 를 애플답게     **완료 (2026-08-18).**
      기준은 시스템 설정 → 일반 → 소프트웨어 업데이트. 거기서 가져온 세 가지:
      · **행에 색 글리프를 안 쓴다.** 애플의 색 둥근사각 아이콘은 **사이드바** 것

        뿐이고, 거기서 색은 이미 보고 있는 것을 꾸미는 일이다. 파란 시계와 주황
        망치를 뺐다.
      · **막는 사실은 각주가 아니라 상태 줄이다.** "다운로드할 수 없음" 이 제목
        바로 밑 빨간 줄에 있고, 그 해법은 자기 행과 자기 버튼을 갖는다. 우리는
        같은 문장을 섹션 푸터에 두고 있었다 — 버튼이 왜 소용없는지가 아니라
        면책 문구처럼 읽혔다.
      · **끝에 붙는 건 ⓘ 지 chevron 이 아니다.** 이 행들은 파고드는 게 아니라
        설명한다.
      마무리(2026-08-18): **"Update Now" 가 웹페이지를 열고 있었다.** 바로 밑
      줄이 "여기서 설치할 수 없음" 이라고 적혀 있는데 눈에 띄는 버튼이 그
      문장과 모순이었다 → "Download…". 막는 줄이 들고 있던 같은 일 하는 두
      번째 버튼도 뺐다 — 상태 줄은 바로 위에 동작이 있으면 자기 버튼이 필요
      없다. 그리고 `update.rs::install_binary` 삭제: 죽은 코드이면서 이 제품이
      **쓸 수 없는** 모델이었다(.app 안 실행 파일만 갈아끼우면 Frameworks·
      Resources 가 옛 버전으로 남고 번들 서명이 깨진다). 완성돼 보이는 죽은
      코드는 누가 배선하라는 초대장이라 남기지 않았다.

✅ 코드 접기(fold)              **완료 (2026-08-18).**
      `fold.rs` 는 이미 완성품이었다 — 들여쓰기 범위 · 닫힘 집합 · O(1) hidden
      인덱스 · 자체 테스트. **빠진 건 아무도 그걸 안 물어봤다는 것.** 워크스페이스
      전체에서 `is_hidden` 을 보는 곳이 한 군데(방금 닫은 접기에서 커서 빼내기)
      였고 뭘 그릴지는 어디서도 안 물었다. 소스가 설명하는데 제품이 안 하는
      기능은 없는 것보다 나쁘다 — 코드를 읽는 게 알아내는 방법이니까.
      · 고친 사실은 하나: **숨은 행은 시각 행을 0개 차지한다.** 그리고 그건
        `WrapMap` — 버퍼행↔시각행의 유일한 주인 — 에 들어간다. 렌더러에 넣었으면
        밴드는 행을 건너뛰는데 스크롤바는 계속 세는 상태가 됐다.
      · 함정: `WrapMap` 이 **버퍼 버전**으로 캐시하는데 접기는 한 바이트도 안
        바꾼다. 자기 키 기준으론 유효한 채 틀린 문서를 설명했을 상태 →
        `FoldState::generation` 을 키에 넣고 그걸 잡는 테스트도 뒀다.
      · `rows_of` 의 `.max(1)` 을 뺐다. 높이 0 인 행을 막던 가드인데 이제 그게
        요점이다. 문서에 없는 행에만 남겼다.
      · 밴드는 `next_visible` 로 걷는다 — 닫힌 접기를 **한 번에** 넘고 예산은
        **그린 행**을 센다. 걸은 행을 셌으면 접기 안에서 밴드를 다 쓰고 그 아래를
        못 그렸고, 한 행씩 넘었으면 10만 줄짜리 접기가 프레임당 10만 번이었다.
      · **제스처 둘, 일부러 하나로 안 합쳤다.** `App::fold_toggle` 은 vim `za` —
        본문 행에서 감싸는 블록으로 간다(캐럿이 안에 있을 때 맞는 규칙).
        `Engine::fold_toggle_row` 는 거터 삼각형 — **헤더 전용**. 삼각형은 헤더
        에만 그려지니 안 누른 블록이 접히면 제스처가 겨눈 것과 어긋난다.
      · 키(⌥⌘←/→)는 **방향성**이다. 토글이면 키 반복에 펄럭인다.
      · 닫히는 접기 안의 캐럿은 헤더로 끌어올린다. 안 그러면 아무도 못 보는
        줄에 앉아서 다음 타건이 화면 밖 텍스트를 고친다.
      테스트 17개.

✅ 저장 시 포맷                  **완료 (2026-08-18). 기본 꺼짐.**
      포매터는 언어 서버고 언어 서버는 내킬 때 답한다 → 저장이 **비동기**가 된다.
      ⌘S 가 요청하고, 답이 오면 펌프가 쓴다.
      · **이 기능의 위험은 전부 "저장을 잃는" 쪽 하나다.** 그래서 포맷을 안 하는
        모든 경로가 곧장 평범한 쓰기로 떨어지고, 안 답하는 포매터는 750ms 뒤

        이 기능은 없는 것보다 나쁘다.
      · **"고칠 것 없음" 도 답이다.** 그 응답은 `pending_edits` 를 안 채운다 —
        편집을 기다리는 설계였으면 이미 깔끔한 파일은 저장할 때마다 타임아웃까지
        멈췄다. → `lsp.formatting_answered`.
      · **기다리는 동안 타이핑하면 그 타건이 이긴다.** 포맷 응답은 버퍼 **전체

✅ 열 선택(블록 선택)            **완료 (2026-08-18).**
      새로운 선택 종류가 아니다. **행마다 보통 선택 하나, 전부 같은 두 열** —
      `SelectionSet::spans` 가 이미 담는 모양이고 멀티커서 편집 기계가 그대로
      먹는다. 아래쪽 어느 것도 새 모양을 배우지 않았다.
      · 열은 **시각 열**이고 그게 어려움의 전부다. 사각형은 화면 위의 사각형인데
        탭은 한 글자 네 칸, `한` 은 한 글자 두 칸이다. 문자 열로 잡으면 열 편집이
        존재하는 이유인 바로 그 텍스트(들여쓴 블록·표)에서 삐뚤어진다.
      · **앵커는 `Position` 이 아니라 화면 열.** 블록은 짧은 줄 끝 너머에서
        시작할 수 있다(세 글자 줄의 40열). `mouse.drag_anchor` 는 Position 이라
        들어오는 길에 3열로 잘리고, 그러면 아래로 끈 블록이 3열에서 시작한다.
      · **블록 왼쪽에 못 닿는 짧은 줄은 줄 끝에 캐럿을 남긴다.** 빼버리면 들쭉날쭉한
        블록에 타이핑할 때 짧은 줄만 조용히 빠진다.
      · 이 기능이 드러낸 구멍: **씬은 줄마다 선택 스팬을 하나 그리고 그걸 primary
        에서 가져왔다.** ⌘-클릭 멀티커서는 전부 캐럿이라 지금껏 안 보였고,
        블록은 **모든 선택에 폭이 있는 첫 사례**였다 → `App::selection_on_row`.
      · ⌥ 는 **누를 때 읽고 제스처 내내 고정**(Xcode 규칙). 추적 루프에서 실시간
        으로 읽으면 손가락이 키에서 떨어지는 순간 드래그의 의미가 바뀐다.
      · 블록은 CoreText 가 아니라 **셀 격자** 경로로 간다. 그리고 `blockHit` 은
        `absoluteHit` 이 내림하는 자리에서 **반올림**한다 — 캐럿은 칸 안에 있지만
        사각형의 양 끝은 칸 사이의 경계다.
      · ⌃⇧↑/↓ 로도 키운다(Xcode 와 같은 코드, 재바인딩 가능). 맨 캐럿에서는
        위/아래로 캐럿 추가 — 캐럿의 열은 폭 0 인 사각형이니 같은 동작이다.
      테스트 24개(코어 17 + 엔진 7).

✅ 코드 접기                     **완료 (2026-08-18).** 조사하다 나온 것.
      `fold.rs` 는 **이미 완성품**이었다 — 들여쓰기 범위·닫힘 집합·O(1) hidden
      인덱스·자체 테스트, 그리고 `App::fold_toggle` 이 그걸 부르고 있었다.
      그런데 워크스페이스 전체에서 `is_hidden` 을 보는 곳이 **딱 한 군데**였다:
      방금 닫은 접기에서 커서를 빼내는 코드. **뭘 그릴지는 아무도 안 물었다.**
      접으면 메시지가 뜨고 커서가 움직이고 화면은 그대로였다.
      소스가 있다고 말하는데 제품이 안 하는 기능은 아예 없는 것보다 나쁘다.
      코드를 읽는 게 알아내는 방법이니까.
      · 고친 것은 사실 하나 — **숨은 행은 시각 행을 0개 차지한다** — 이고
        그건 `WrapMap` 에 산다. 버퍼행↔시각행의 유일한 소유자. 렌더러에 넣었으면
        스크롤 범위·스크롤바·히트테스트가 파일 높이를 두고 서로 다른 말을 했다.
      · `WrapMap` 은 **버퍼 버전**으로 캐시했는데 접기는 한 바이트도 안 바꾼다 →
        자기 키 기준으로는 유효한 채 틀린 문서를 설명했을 것. `FoldState` 에
        generation 을 달아 키에 넣었다. `rows_of` 의 `.max(1)` 은 뺐다 — 높이 0인
        행을 막는 가드였는데 이제 그게 요점이다.
      · 밴드는 `next_visible` 로 돌고 예산은 **그린 행**을 센다. 걸은 행을 세면
        닫힌 접기 안에서 밴드를 다 쓰고 그 아래를 안 그린다. 한 행씩 뛰면
        10만 줄짜리 닫힌 접기가 프레임마다 10만 번 조회한다(5000줄 테스트 있음).
      · **제스처 둘, 일부러 안 합쳤다.** `App::fold_toggle` 은 vim `za` —
        본문 행에서 **감싸는 블록**으로 간다(커서가 안에 있을 때 누른 키니까).
        거터 삼각형은 **헤더 전용** — 삼각형은 헤더에만 그려지고, 클릭이 사용자가
        안 누른 블록을 접으면 제스처가 겨눈 것과 다른 말을 하는 것이다.
      · 접히는 블록 안에 있던 커서는 헤더로 끌어올린다. 안 그러면 아무도 못 보는
        줄에 커서가 앉아 다음 타건이 화면 밖 텍스트를 고친다.
      · 삼각형은 글리프가 아니라 **채운 삼각형**(6pt 라 1x 에서 획이 뭉갬),
        열림 아래·닫힘 오른쪽(맥 disclosure 규약 = 동작이 아니라 **상태**),
        닫힘만 진하게(줄이 사라진 이유가 보여야 함).
      · ⌥⌘←/→, ⌥⇧⌘←/→ (Xcode 코드, 재바인딩 가능). 키는 **방향성** —
        토글이면 키 반복에 블록이 펄럭인다.
      · 접기 상태는 ABI **끝에 덧붙였다**. 위 필드는 전부 Swift 가 하드코딩된
        오프셋으로 읽는다.
      테스트 17개.

◐ 21. 컴포넌트 다운로드          → docs/SUISEI-COMPONENTS-PLAN.md
      **C3(UI) + C4(툴 감지) 완료 (2026-08-18)** — Settings → Components.
      · 계측이 답을 바꿔놓았다: **디버거는 0 MB 다.** Rust·C·C++·ObjC 는
        Xcode 안의 `lldb-dap`, Python·Go·Node 는 pip·go·npm 의 debugpy·dlv·
        js-debug. 우리 사본을 호스팅하면 애플이 이미 갱신하는 디버거를 하나 더
        얹고 그 CVE 까지 떠안는 것. LSP 도 같은 논리.
      · 그래서 디버깅의 "컴포넌트"는 바이너리가 아니라 **뭐가 있는지 찾아주고
        없는 건 설치를 도와주는 것**이고, 그건 서명 없이도 오늘 되는 절반이다.
      · `crate::exec`, PATH 아님 — Finder 로 띄운 앱은 `/usr/bin:/bin` 만
        물려받아서 Homebrew·cargo·애플 툴체인이 전부 안 보인다. lldb-dap 을 두 벌
        가진 맥에 "설치하세요"라고 했던 그 버그. **자기 소스를 grep 하는 테스트로
        못 박아뒀다**(주석 말고 코드만 본다 — 첫 판은 규칙을 설명한 문장에
        스스로 걸렸다).
      · LSP 행은 `config::lsp_lang_catalog` 에서 온다. 설정이 쓰는 그 표.
        `install_hint` 를 쪼개서 페이지의 복사용 명령과 에디터 에러 메시지가
        **한 사실**이 되게 했다.
      · FFI 는 **엔진 포인터를 안 받는다.** `catalog()` 가 App 상태를 안 건드리니
        백그라운드 스레드에서 부를 수 있고, 그래야 한다 — debugpy 는 콘솔
        스크립트가 없어서 인터프리터가 import 되는지가 유일하게 정직한 검사이고
        그건 프로세스 시작이다. 엔진을 태웠으면 메인 스레드가 그걸 기다렸다.
      · Run 이 아니라 **Copy**. 사용자 툴체인으로 전역 설치하는 명령을 설정
        페이지가 대신 실행해주는 건 설정 페이지가 기계를 바꾸는 것.
      남은 것: C0(히어로 jpeg 19MB 재인코딩, 지금 가능) · C1/C2(문법을 dylib 로,
      서명·노터라이즈 필요 = **P0-2 뒤**) · C5(Assimp dylib 화).

✋ Run/Build 콘솔이 stdin 을 안 준다.
   입력을 기다리는 프로그램은 터미널에서 돌려야 한다.

✋ 문제 목록은 **마지막 한 번의 실행** 것이다.
   새 실행이 이전 진단을 지운다 — 의도한 것(어제의 물결선은 오늘의 답이
   아니다)이지만, 실행 사이에 파일을 고치면 낡은 물결선이 잠깐 남는다.
   LSP 가 같은 줄을 이미 말하고 있어서 실제로는 잘 안 보인다.

✋ refresh_syntax 가 버전마다 워커에 넘기는 전체 텍스트 스냅샷.
   **릴리스에서 키당 0.101ms(그중 스냅샷 0.081ms)** = 120fps 프레임 예산의 1.2%.
   예전 기록의 1.99ms 는 디버그 빌드 숫자였다. 편집만 보내는 설계는 여전히
   타당하지만, 지금 하면 측정되지 않은 이득을 위해 core 와 워커가 텍스트에
   대해 서로 다르게 알 수 있는 상태를 새로 만드는 거래가 된다.

✋ `.js` 파일의 멀티메가바이트 한 줄은 tree-sitter 파스 자체가 2초 걸린다.
   쿼리는 480열에서 멈추게 고쳤다(8MB 17.4s → 2.0s). 남은 2초는 진짜 파싱이고
   문법 워커 스레드에 있어서 UI 는 안 멈춘다.
