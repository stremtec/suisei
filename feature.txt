이 파일은 **열려 있는 것만** 적는다. 끝난 것은 docs/FEATURE-LOG.md 로 갔다.
2026-08-18 정리 전에는 한 파일이었고, 한 항목이 두 곳에 **반대 상태로** 적혀
있는 일이 흔했다 — 상단 목록은 ✅ 인데 본문은 ☐. 항목은 여기 한 번만 나온다.

설계가 끝난 것은 본문을 여기 옮겨 적지 않고 docs/ 를 가리킨다. 문서가 본문이다.

═══════════════════════════════════════════════════════════════════════════
 P0 · 출시 준비 — 지금 제일 위
═══════════════════════════════════════════════════════════════════════════
셋은 순서가 있다. 라이선스가 먼저인 이유는 나머지 둘이 그걸 따라가기 때문 —
dmg 안에 들어가는 EULA, About/Welcome 문구, 저장소의 LICENSE 가 전부 한 결정의
결과다. 거꾸로 하면 두 번 만든다.

☐ 1. 라이선스 결정             **먼저 정할 것. 지금 문서와 충돌한다.**
      메모: "오픈소스지만 상업이용만 불가로."
      그런데 docs/SUISEI-LICENSE-POLICY.md 는 **"Suisei는 클로즈드 소스다"** 로
      시작하고, 3층 구조(LICENSE = 1년 지연 공개 dev 스냅샷 / EULA = 배포
      바이너리 / 현재 소스는 비공개)를 법률 리뷰까지 거쳐 적어놨다.
      "오픈소스 + 비상업" 은 그 정책의 반전이지 조정이 아니다.
      → 정책 자체를 바꾸는 것인지, 아니면 **공개되는 층(지연 공개 dev 스냅샷)의
        조건만** 비상업 허용으로 바꾸는 것인지 먼저 정해야 한다. 후자라면 지금
        정책과 모순이 없고 LICENSE 본문만 손대면 된다.
      · 참고: "오픈소스" 와 "상업이용 불가" 는 OSI 정의상 양립하지 않는다
        (OSD 6조). 배포야 얼마든지 가능하지만 "오픈소스"라고 부르면 반박당한다 —
        source-available 이라고 쓰는 편이 사실이고 시비가 없다.
      · 손댈 곳: LICENSE · EULA · docs/SUISEI-LICENSE-POLICY.md · About/Welcome.

☐ 2. dmg 패키징                 지금은 `.app` 까지만 나온다.
      scripts/package-suisei-app.sh 가 번들·프레임워크 임베드·아이콘·폰트까지
      하고 `codesign --sign -` 로 **ad-hoc 서명**만 한다. 남은 것:
      · 진짜 Developer ID 서명 (ad-hoc 은 다른 기계에서 Gatekeeper 에 막힌다)
      · 노터라이즈 + 스테이플
      · dmg 레이아웃 (배경, /Applications 심볼릭 링크, 창 크기·아이콘 위치)
      · 안에 EULA 넣기 — P0-1 이 정해진 뒤에.
      막는 것: 유료 개발자 계정과 서명 인증서. 그게 없으면 나머지는 준비만 된다.

☐ 3. 업데이트 UI 를 애플답게     메모: "색 들어간 아이콘 색 없는거로."
      시스템 설정의 소프트웨어 업데이트가 기준 — 아이콘은 단색, 상태는 색이
      아니라 글자로. 지금은 색 아이콘이라 시스템 UI 옆에 놓으면 튄다.

☐ 단축키 변경                   Shortcuts 페이지가 **읽기 전용**이다.
      막는 것 하나: core 에 바인딩을 바꾸는 API 자체가 없다. 표도 있고 화면도

        것과 같은 선).

        뷰로 그린다.** 표는 Grid, 코드 블록은 배경 있는 뷰, 인용은 왼쪽 괘선.
        구조 변경이라 P0 뒤에.
      (지금 상태: 문단은 접히고 제목 밑줄은 진짜 선이다. 표는 아직 문자.)

═══════════════════════════════════════════════════════════════════════════
 알고 안 고침
═══════════════════════════════════════════════════════════════════════════
✋ Run/Build 콘솔이 stdin 을 안 준다.
   입력을 기다리는 프로그램은 터미널에서 돌려야 한다.

✋ 문제 목록은 **마지막 한 번의 실행** 것이다.
   새 실행이 이전 진단을 지운다 — 의도한 것(어제의 물결선은 오늘의 답이
   아니다)이지만, 실행 사이에 파일을 고치면 낡은 물결선이 잠깐 남는다.
   LSP 가 같은 줄을 이미 말하고 있어서 실제로는 잘 안 보인다.

✋ refresh_syntax 가 버전마다 워커에 넘기는 전체 텍스트 스냅샷.
   **릴리스에서 키당 0.101ms(그중 스냅샷 0.081ms)** = 120fps 프레임 예산의 1.2%.
   예전 기록의 1.99ms 는 디버그 빌드 숫자였다. 편집만 보내는 설계는 여전히
   타당하지만, 지금 하면 측정되지 않은 이득을 위해 core 와 워커가 텍스트에
   대해 서로 다르게 알 수 있는 상태를 새로 만드는 거래가 된다.

✋ `.js` 파일의 멀티메가바이트 한 줄은 tree-sitter 파스 자체가 2초 걸린다.
   쿼리는 480열에서 멈추게 고쳤다(8MB 17.4s → 2.0s). 남은 2초는 진짜 파싱이고
   문법 워커 스레드에 있어서 UI 는 안 멈춘다.
